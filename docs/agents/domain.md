# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

Before exploring the codebase, read the glossary and any ADRs relevant
to the work. If they do not exist, proceed silently. Create them through
domain modeling when terms or decisions are resolved.

Use the glossary's vocabulary in issues, proposals, code, and tests.
Surface conflicts with existing ADRs explicitly.

Product behavior remains governed by `docs/PRD.md`,
`docs/DATA_MODEL.md`, and `docs/IMPLEMENTATION_PLAN.md`.
